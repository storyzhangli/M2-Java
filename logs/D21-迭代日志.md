## 阶段 B：Usage/观测/Tracing 设计（任务 #98）

- 字节码级确认 Spring AI 可移植 Usage 的两个陷阱：默认 getTotalTokens 把 null 当 0 相加，DefaultUsage 把 null 字段强制成 0，无法区分缺失与真实 0。
- 确认 DeepSeek 原生 DeepSeekApi.Usage 是保留 null 的 record，确定「原生优先、可移植回退」的归一化策略。
- 确定观测收口在「逻辑调用」层：观测在韧性层之外创建，覆盖全部重试但只在终态写一条；三终态 SUCCESS/ERROR/CANCELLED 用 AtomicBoolean 互斥。
- 确定跨线程方案：requestId 在 Servlet 线程从 MDC 捕获为对象字段，Reactor 线程不依赖 ThreadLocal 传播。

## 阶段 C：实现 TraceId/脱敏记录/延迟/Usage（任务 #99）

- 新增 observability 包 8 个类型：ModelCallRecorder、ModelCallObservation、ModelCallRecord、CallOutcome、UsageStatus、UsageSource、TokenUsageSnapshot、ModelObservabilityProperties。
- DeepSeekAiChatService 接入：构造器注入 recorder；新增 observeBlocking/observeStream 统一收口，同步/流式（含思考模式、角色链路）全部接入；删除完整 Prompt/响应日志点。
- application.yml 新增 app.model-observability 段（enabled、record-time-to-first-chunk，均带环境变量占位）。
- 关键实现：单行 JSON 经专用 Mapper（关闭 default typing、空 Bean 不报错）输出，emit 全兜底；durationMs/TTFT 用 System.nanoTime 单调时钟；流式 usage 只覆盖 lastUsage 不相加。
