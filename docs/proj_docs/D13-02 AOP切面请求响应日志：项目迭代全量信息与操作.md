## 第 3 章 总体设计与组件职责

### 3.1 为什么是“过滤器 + AOP”双层，而不是只用 AOP

Spring AOP 基于动态代理，只能拦截“被代理 Bean 的方法调用”，它**天然覆盖不了完整 HTTP 生命周期**：拿不到最终 HTTP 状态码、拿不到异常处理器写出的响应体、也覆盖不到未进入 Controller 的请求。因此采用双层分工：

- **过滤器层（Servlet 边界）**：覆盖完整 HTTP 生命周期，负责 requestId 透传、请求/响应字节缓存、最终状态码与响应体记录，且能兜住未进入 Controller 的请求。
- **AOP 层（Controller 边界）**：记录 Jackson 绑定后的 DTO 入参、Controller 返回对象、方法级耗时与业务异常类型，语义更贴近业务。

### 3.2 组件总览

```
客户端请求
   │
   ▼
TraceIdFilter（最高优先级）  生成/接收 requestId → MDC → 响应头
   │
   ▼
CachedBodyAccessLogFilter   包装请求/响应 → chain → 记录 HTTP 事件 → copyBodyToResponse
   │
   ▼
DispatcherServlet → GlobalExceptionHandler（既有，异常归一）
   │
   ▼
ControllerAccessLogAspect   @Around 记录方法入参/返回/耗时/异常（原样抛出）
   │
   ▼
ChatController / AiChatService（既有业务，零改动）
```

### 3.3 四个事件类型与一个专用 Logger

所有访问日志事件都写入名为 **`ACCESS_LOG`** 的 SLF4J Logger，输出为**单行 JSON**（天然转义换行/引号，防日志伪造）：

| event | 产出组件 | 关键字段 |
|---|---|---|
| `HTTP_REQUEST` | CachedBodyAccessLogFilter | method、uri、query、clientIp、headers（脱敏）、requestBody |
| `HTTP_RESPONSE` | CachedBodyAccessLogFilter | httpStatus、elapsedMs、responseBody、exception（若过滤器链抛出） |
| `CONTROLLER_ACCESS` | ControllerAccessLogAspect | controllerMethod、args、result、方法级 elapsedMs |
| `CONTROLLER_ERROR` | ControllerAccessLogAspect | exception 全类名、errorMessage、方法级 elapsedMs |

## 第 5 章 配置项说明（application.yml）

```yaml

  access-log:
    enabled: ${ACCESS_LOG_ENABLED:true}      # 总开关，false 时过滤器与切面均不装配
    request-id-header: X-Request-Id          # 请求/响应中承载 requestId 的头名
```

## 第 8 章 关键边界、已知限制与如实声明

1. **未匹配路径在本项目不是 404**：Spring Boot 3 / Framework 6 对无静态资源的路径抛 `NoResourceFoundException`，但本项目 `GlobalExceptionHandler` 的兜底 `@ExceptionHandler(Exception.class)` 将其归一为 **HTTP 200 + body code 5000**。这是既有“HTTP 恒 200、body.code 区分错误”契约的真实表现，本次按最小改动原则**不改变该语义**。若将来要标准 404，应新增专用 `@ExceptionHandler(NoResourceFoundException.class)` 并明确设置状态码，属独立迭代。
2. **AOP 的代理局限**：同类内部 `this.method()` 自调用绕过代理、不触发 Advice；当前 Controller 入口均由 DispatcherServlet 外部调用，不受影响。
3. **请求体缓存前提**：`ContentCachingRequestWrapper` 只缓存“被框架读取过”的字节。GET 无体或请求未进入 Controller 时为空，日志以 `skipReason` 说明，不做臆造。
4. **响应体必须回写**：使用 `ContentCachingResponseWrapper` 必须在 finally 调用 `copyBodyToResponse()`，否则客户端收到空响应；已在代码中保证并由真实容器测试守护。
5. **二进制/流式分支**：multipart、octet-stream、image/video/audio、SSE 等只记 Content-Type/大小/跳过原因，逻辑已编码并有单测，但本模块没有对应端点，**未做运行期实证**。
6. **异步线程 MDC 传递**：本模块当前没有线程池/`@Async` 场景，未引入跨线程 MDC 装饰器；后续若引入异步，需额外做 MDC 桥接与用完清理。
7. **控制台中文乱码仅为捕获编码问题**：Surefire 在 PowerShell 控制台回显中文可能显示乱码，日志文件本身为 UTF-8，已用文件读取确认中文正常。
