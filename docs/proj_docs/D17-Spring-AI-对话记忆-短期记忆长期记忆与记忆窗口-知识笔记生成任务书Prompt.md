## 3.2 必须明确的概念边界

必须逐条解释：

1. **聊天记录不等于对话记忆。** 聊天记录通常追求完整留存、审计、回放和业务查询；对话记忆关注当前请求中哪些信息值得重新提供给模型。二者可以共用底层存储，但生命周期、查询目的、裁剪规则和访问接口不应混为一谈。
2. **短期记忆不等于只存内存。** 短期描述的是信息在对话任务中的作用与时间范围，不代表它只能存放在 JVM 内存。短期消息可以由数据库 Repository 持久化。
3. **长期记忆不等于无限聊天记录。** 长期记忆通常经过筛选、提取、归纳、去重、更新、过期处理和按需检索；直接把几千条历史消息全部塞进 Prompt 既不经济，也不等于高质量记忆。
4. **长期记忆不等于 RAG 知识库。** 用户偏好、用户事实、跨会话任务状态属于个性化记忆；产品手册、技术文档、制度文件属于外部知识。两者可以使用相似的向量检索基础设施，但数据来源、权限、更新策略和提示词语义不同。
5. **`MessageWindowChatMemory` 的消息数量窗口不等于模型 Token 上下文窗口。** `maxMessages` 是消息数量上限策略，不是 Token 数上限；一条消息可能很长，若只按条数控制，仍可能超过模型可用上下文。
6. **记忆存储不代表模型永久记住。** 模型本身通常按单次请求接收 Prompt；应用在下一次调用时主动检索并重新提供相关消息或记忆，才能形成跨轮次连续性。
7. **Conversation ID 不等于身份认证与授权。** 它用于定位/隔离会话记忆，不应该单独作为用户身份凭据；服务端仍需验证当前用户是否有权读取、追加或删除该会话。

必须给出一个术语对照表，列出“概念、解决的问题、典型数据、存储位置、进入模型上下文的方式、是否要求完整保存”。

| Chat History | 回放、审计、用户查看、业务记录 | 通常要求完整 | 按会话、时间、消息 ID | 否 |
| Short-term Chat Memory | 维持当前会话连续性 | 保留当前任务所需部分 | Conversation ID + 窗口 | 选择性进入 |
| Long-term Memory | 跨会话个性化、事实和任务连续性 | 经过筛选和治理 | 结构化查询、语义检索、摘要 | 选择性进入 |
| RAG Knowledge | 提供外部可信知识 | 以权威知识源为准 | 向量/关键词/混合检索 | 选择性进入 |

必须提供典型场景：

- “我刚才说的设备编号是什么？”——最近短期记忆或完整会话记录；
- “记住我负责 A 产线，以后回答优先考虑这条产线。”——经授权确认的长期用户事实；
- “查一下设备手册中的故障代码 E101。”——RAG 外部知识检索；
- “展示上周所有对话内容。”——完整聊天历史查询，而不是 ChatMemory 窗口。

## 4.9 Conversation ID、多用户隔离与并发
