## 第一章 迭代背景、目标与边界

### 1.1 背景

D14 模块由 D01/D13 的 Spring AI 初始化工程复制演进，已有能力包括：

- 同步对话接口 `POST /api/v1/ai/chat`、健康检查 `GET /api/v1/ai/health`；
- `mock` / `deepseek` 双模式条件装配，默认离线 mock，零外网依赖；
- D13 交付的 AOP + Filter 访问日志体系（TraceId、出入参脱敏、MDC 链路）。

同步接口必须等整句生成完毕才能返回，用户在等待期间看不到任何输出。本次迭代在**不切换容器、不引入新框架**的前提下，增加服务器推送事件（SSE，Server-Sent Events）流式对话能力，并提供一个可直接使用的最小前端对话页面。

### 1.2 本次目标

1. 新增流式对话接口 `POST /api/v1/ai/chat/stream`，按 `start → delta* → complete`（异常时 `error`）协议增量推送；
2. 在 Spring Boot `static/` 下交付原生 HTML/CSS/JS 单页：增量渲染、停止、新对话、错误态、纯文本防 XSS；
3. mock 模式与 deepseek 模式均提供流式实现，mock 模式可离线完整演示；
4. 不破坏 D01/D13 既有功能，全量测试通过，并做一次真实启动联调；
5. 同步交付两份 Markdown 文档、迭代日志，临时资料带 `D14` 前缀归档且**不自动删除**。

## 第四章 设计决策摘要

1. **MVC 异步而非 WebFlux**：`SseEmitter` 是 Spring MVC 官方支持的异步返回值，配合 Tomcat 异步请求即可推送流；`Flux` 只在业务层作为流式数据结构使用，订阅在控制器内显式管理。
2. **POST + fetch 而非 EventSource**：原生 `EventSource` 只支持 GET、无法携带 JSON 请求体与自定义鉴权头；接口契约是 POST JSON，因此前端用 `fetch` + `ReadableStream` 自行按 SSE 帧协议解析。
3. **异常分两期处理**：响应头提交前（参数校验、密钥拦截）走既有 `GlobalExceptionHandler` 返回统一 JSON；响应头提交后只能在 SSE 协议内下发 `error` 事件再关闭，错误码口径与同步接口一致（4001/5001/5002/5000）。
4. **流式路径排除正文缓存过滤器**：D13 的 `ContentCachingResponseWrapper` 会缓冲整段响应并在过滤器收尾时才回写，与异步增量推送天然冲突（详见第六章故障 4），将 `/api/v1/ai/chat/stream` 加入 `app.access-log.exclude-paths`；TraceIdFilter 独立注册，requestId 不受影响。
5. **并发发送收口到 `safeSend`**：reactor 回调线程与容器超时/断连回调可能并发写 emitter，统一在 emitter 对象上加锁，并用 `AtomicBoolean finished` 保证幂等。

## 第六章 过程故障与修复记录（真实发生，非演练）

全量测试首轮结果为 **36 用例、4 失败、0 错误、1 跳过**，逐一通过 surefire 报告定位并修复：

### 故障 1：两个访问日志测试缺少 CONTROLLER_ACCESS 事件

- 现象：`AccessLogIntegrationTest`、`AccessLogRealContainerTest` 断言三类事件，实际只有 `HTTP_REQUEST/HTTP_RESPONSE`；
- 根因：D14 从 D01 复制后包名已迁移为 `com.zl.d14.controller`，但切面切点仍写死 `execution(public * com.zl.d01.springai.controller..*.*(..))`，AOP 在 D14 从未命中——属于**骨架迁移遗留缺陷**，与本次 SSE 改动无关，但导致套件非全绿；
- 修复：切点改为 `com.zl.d14.controller..*`，并让切面遇到 `ResponseBodyEmitter` 只输出 `<async-emitter:SseEmitter>` 占位。

### 故障 2：Mock 服务反射结构断言失败

- 现象：`MockNoExternalApiTest.mockServiceShouldHaveNoModelOrHttpClientDependency` 期望 `getDeclaredFields()` 为空、仅一个无参构造，实际多出 `CHUNK_SIZE/CHUNK_INTERVAL` 两个静态字段；
- 根因：初版把分块参数提升为静态常量，违反既有测试对“模拟服务结构上无法持有任何依赖”的强约束；
- 修复：删除全部字段，6 与 `Duration.ofMillis(15)` 内联为方法内局部值，类恢复零字段、隐式无参构造。

### 故障 3（测试代码自身）

- 笔误 `"data:".length`（字段访问，String 无此字段）与测试方法漏写 `throws Exception`，编译期暴露后立即修正，未进入运行期。

### 故障 4：SSE 真机只收到 start，没有 delta/complete

- 现象：`ChatStreamIntegrationTest` 帧序列断言失败，实际仅 `["start"]`；
- 根因：`CachedBodyAccessLogFilter` 对所有响应套 `ContentCachingResponseWrapper`，SSE 开启异步后过滤器链立即返回、`finally` 中过早执行 `copyBodyToResponse()`，后续 reactor 增量继续写入包装器却再无刷出时机，流被截断；
- 修复：流式端点加入 `app.access-log.exclude-paths`，不做请求/响应正文缓存；真机复测得到完整 24 帧。

### 修复后结果

`Tests run: 36, Failures: 0, Errors: 0, Skipped: 1`，`BUILD SUCCESS`。唯一跳过项 `DeepSeekLiveSmokeTest` 为无密钥条件下的设计性禁用。

## 第十一章 验收整改补充（2026-10-28）

本章只记录对首版交付的增量修正，首版历史章节原文保留；整改的完整过程与证据另见同目录《D14-验收问题整改-项目迭代全量记录.md》。

1. **后端超时缺陷修复**：原 `onTimeout` 先置 `finished=true` 再发 error 事件，被 `safeSend` 的终态判断拦截，超时事件必然丢失。整改后采用双层超时——Flux 增加 `.timeout()` 应用层主超时（连接健康时经 onError 通道发 5000 超时事件并取消上游），SseEmitter 容器超时保留 5 秒余量兜底，兜底回调在锁内按“先发 error、再置位、再 complete”执行。
2. **前端分帧缺陷修复**：原解析只按 `\n\n` 切帧，不兼容标准允许的 CRLF（`\r\n\r\n`）与 CR（`\r\r`）。分帧逻辑抽取为 `static/js/sse-parser.js`，兼容三种行结束符及跨块/跨 UTF-8 字节边界，并新增 9 个 Node 原生测试用例。
3. **测试加固**：新增 `ChatStreamTimeoutTest`（超时事件、上游取消、连接收尾三断言）与 `src/test/node/sse-parser.test.js`；全量重测结果以整改文档与 `docs/evidence/D14-remediation/` 入库证据为准。
4. **学习材料勘误**：知识笔记与费曼口述稿中 `ChatClient.call()` 执行时机、HTTP chunked/HTTP2 帧/SSE 协议分层、Flux 背压边界三处概念错误已修订。
