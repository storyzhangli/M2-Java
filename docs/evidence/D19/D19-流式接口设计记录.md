# D19 流式接口设计记录

> 说明：流式主代码骨架已存在，本记录固化其契约与设计，并明确测试落点；不复制第二套业务逻辑。

## 1. 接口契约

| 项 | 同步接口（不变） | 流式接口（新增/已建） |
|---|---|---|
| 路径 | POST /api/v1/ai/chat | POST /api/v1/ai/chat/stream |
| 媒体类型 | application/json | text/event-stream;charset=UTF-8 |
| 请求 DTO | ChatRequest | ChatRequest（复用，不加差异字段） |
| 成功载体 | Result<ChatReplyResponse/RoleChatReplyResponse> | 命名 SSE 事件 |
| 入参校验 | @Valid + 可配置长度 | 同左，开始前校验失败直接走全局异常返回 JSON |

SSE 事件（data 均为 JSON，事件名显式下发）：

| 事件 | 载荷 | 时机 |
|---|---|---|
| start | requestId/mode/model/sessionId（角色另含 scene/templateId/version/thinking） | 订阅时首个 |
| thinking | seq + content | 仅 showReasoning 且有推理分片 |
| delta | seq 从 0 递增 + content | 每个答案片段 |
| citations | 引用列表 | complete 前，有命中才发 |
| complete | seq/mode/model/mocked/totalChars/thinking | 正常结束 |
| error | code + 固定文案 | 异常/超时，不含堆栈/密钥 |

## 2. 共享业务逻辑

- 统一准备链：参数校验 → resolveOwner 归属 → 场景分支（有 scene 走 RoleConversationService.prepare 渲染模板，无 scene 直接 startTurn）→ 上下文窗口 → ChatInvocation。
- 同步与流式仅在「模型调用 + 响应适配」分叉：
  - 同步：orchestrator.chat → 完整结果。
  - 流式：orchestrator.stream → Flux<StreamChunk>。
- 不在 Reactor 流中 block/collectList 重新聚合；不用脱离请求生命周期的 subscribe 启动后台；由 Web 层（SseEmitter 回调）管理订阅。

## 3. 生命周期与失败行为

- 正常：start → 多个 delta（可能有 thinking/citations）→ complete。
- 上游异常：Reactor onError → 落 FAILED → 发 error 事件 → complete 关闭。
- 超时：Flux.timeout(streamTimeoutMs) 抛 TimeoutException；容器 SseEmitter 兜底 onTimeout 再保一层。
- 客户端断开：emitter.onError → dispose 上游；有部分正文落 INTERRUPTED 助手消息，无正文按失败。
- 终态单次保证：persisted AtomicBoolean compareAndSet，防止 Reactor 回调与容器回调重复写。
- 历史记录时点：用户消息流开始前 PENDING；助手全文仅在 complete 时落 COMPLETED；半截内容不标成功。

## 4. 同步接口兼容清单（逐项验证）

- [ ] 路径 /api/v1/ai/chat、方法 POST 不变。
- [ ] 请求 DTO 字段与校验注解不变。
- [ ] Result 结构与业务码 200/4001/5000/5001/5002 不变。
- [ ] 成功响应字段（ChatReplyResponse/RoleChatReplyResponse）不缺失、不新增必填。
- [ ] 既有错误语义（空白/超长/非法场景/归属）不退化。
- [ ] 同步等待行为与前端调用方式不变。

## 6. 不做项

- 不引入 SSE 心跳/事件 ID/Last-Event-ID 重连（无客户端需求）。
- 不新增 WebSocket、消息队列、网关或第二套模型链。
- 不实现复杂逐条背压控制器，沿用取消上游的收敛策略。
